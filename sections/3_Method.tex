\subsection{Problem Setup}
\label{sec:setup}

We represent a software repository as a code graph
$\mathcal{G}=(V,E)$ whose nodes are code units (files, classes,
functions) and whose edges encode structural relations such as
\textit{contains}, \textit{invokes}, and \textit{imports}.
Given a natural-language issue $q$, a first-stage retriever
induces a ranking $\pi$ over $V$ by relevance to $q$. Let
$G \subseteq V$ denote the (unknown at test time) gold set of
nodes that must change to resolve $q$. The task is to return a
length-$K$ list $\hat{L} \subseteq V$ that maximises
\begin{equation}
\text{recall}@K(\hat{L}) \;=\; \frac{|\hat{L} \cap G|}{|G|}.
\label{eq:recall}
\end{equation}

The setting is bounded-context: a small open model cannot
ingest the full ranked list, let alone the repository. The
system observes only a window of $r$ ranked nodes per round and
may issue a bounded number of bounded-size model calls,
precluding single-pass reranking of the candidate pool. We
therefore cast localization as iterative set recovery.

\subsection{Multi-Agent Multi-Turn Scaffolding}
\label{sec:scaffold}

We split the work between a small post-trained \emph{scorer}
and a larger \emph{agent}: the scorer triages a bounded
candidate pool each round, and only the agent commits the
length-$K$ list. A \emph{seed} is a node from which the
scaffolding expands its graph neighborhood via BFS. One round
runs in three steps (Figure~\ref{fig:scaffold}); the loop runs
for at most $R$ rounds or until the ranked list is exhausted.

\paragraph{Step A: seed selection.}
At round $t$ the scaffolding takes the next $r$ unseen entries
of the ranking $\pi$ as the window $W_t$, and the scorer
selects $S$ seeds from $W_t$. If the scorer returns
fewer than $S$ identifiers we pad with the top-ranked remaining
entries of $W_t$.

\paragraph{Step B: neighborhood expansion.}
For each of the $S$ seeds the scaffolding runs a depth-$d$
BFS along structural edges of the code graph
(\textit{contains} by default; edge-type ablations covering
the four relations are left to future work). We
keep only neighbors that also appear in the top-$N$ of $\pi$
(with $N{=}500$ throughout), a cheap rank pre-filter that
removes graph noise without invoking the scorer. The scorer
then keeps the $n$ most relevant survivors per seed, yielding
up to $Sn$ neighbors $\mathcal{N}_t$.

\paragraph{Step C: list update.}
A single agent call sees the issue $q$, the current returned
list $\hat{L}_{t-1}$ (initialised to the top-$K$ of $\pi$ at
$t{=}0$), the window $W_t$, and the scorer-selected neighbors
$\mathcal{N}_t$, and writes back the updated length-$K$ list
$\hat{L}_t$. The agent additionally returns an \emph{early-stop}
flag: if it judges $\hat{L}_t$ to already cover every function
the issue requires, the loop terminates before the round budget
is exhausted and $\hat{L}_t$ becomes the final prediction.
Early stopping is therefore an agent-side decision, traded off
against the token cost of additional rounds.

No call sees more than $r + Sn$ candidates plus $\hat{L}_{t-1}$, so
per-call token cost is roughly constant across rounds and a
32K context comfortably absorbs it. Removing Steps~A and~B
collapses the procedure to a pure window-update loop, giving a
clean ablation that isolates the contribution of graph
exploration, reported as the \emph{w/o graph} block of
Table~\ref{tab:verified}. The final prediction is
$\hat{L} \equiv \hat{L}_R$.

\subsection{Training the Scorer}
\label{sec:training}

The dense per-round shaping signal the scaffolding exposes
telescopes to end-to-end $\text{recall}@K$, so by potential-based
reward shaping \citep{ng1999policy} the dense per-round objective
and the sparse end-to-end metric share the same optimum; we state
and prove the identity in Appendix~\ref{app:proof}. Training the
scorer therefore reduces to supervised learning on labelled
candidate windows rather than reinforcement learning over
multi-step trajectories. We parameterise the scorer as a low-rank
adaptation \citep{hu2022lora} of Qwen2.5-Coder-3B-Instruct
\citep{hui2024qwen25codertechnicalreport}; only the adapter
weights move during training, and no new scoring head is added.
A standalone evaluation of the trained scorer against base
Qwen and GPT-5.3 Codex baselines is reported in
Appendix~\ref{app:results}.

\paragraph{Score readout.}
For an issue $q$ and a candidate function $c$, we form a single
chat-formatted prompt $x(q, c)$ that contains $q$, the
token-truncated source of $c$, and an assistant turn asking whether
$c$ is relevant to $q$. Writing $\ell(x) \in \mathbb{R}^{|V|}$ for
the next-token logits at the final position of $x$, we score $c$ by
the contrast between two fixed vocabulary tokens
($\ell_{+}$ for the \textsc{yes} token, $\ell_{-}$ for \textsc{no}),
\begin{equation}
\begin{aligned}
  s(q,c) &= \ell_{+}\!\bigl(x(q,c)\bigr) - \ell_{-}\!\bigl(x(q,c)\bigr), \\
  p(q,c) &= \sigma\!\bigl(s(q,c)\bigr),
\end{aligned}
  \label{eq:score}
\end{equation}
with $\sigma$ the logistic sigmoid. The language-model head stays
frozen, so the readout adds no parameters.

\paragraph{Training groups.}
Each training instance is a single issue $q$ together with a
\emph{group} of $M$ candidates assembled to mirror the inference
window. The group contains every ground-truth function for $q$
that lies inside the retriever's top-$N$ pool, completed with
non-relevant candidates drawn to span the full rank depth: a fixed
fraction is taken as hard negatives from the top of the pool, and
the remaining slots are filled by one-per-bin sampling across the
deeper pool. Members are position-shuffled so order does not leak
the label, and negatives are re-sampled at the start of every
epoch (Appendix~\ref{app:details}).

\paragraph{Objective.}
Let $s_j := s(q, c_j)$ and $y_j \in \{0,1\}$ be the label of
$c_j$, and write $\mathcal{G} = \{j : y_j = 1\}$ for the indices
of the ground-truth members. The loss combines a pointwise binary
cross-entropy under the sigmoid link of~\eqref{eq:score},
\begin{equation}
\begin{aligned}
  \mathcal{L}_{\text{BCE}}
   = -\frac{1}{M}\sum_{j=1}^{M} \bigl[\,
   &y_j \log \sigma(s_j) \\
   &{}+ (1-y_j) \log(1-\sigma(s_j)) \,\bigr],
\end{aligned}
  \label{eq:bce}
\end{equation}
with a listwise \emph{coverage} term --- a softmax log-likelihood
over the group, evaluated at each ground-truth member and averaged,
\begin{equation}
  \mathcal{L}_{\text{cov}}
  = -\frac{1}{|\mathcal{G}|}\sum_{j \in \mathcal{G}}
    \log \frac{\exp(s_j)}{\sum_{k=1}^{M} \exp(s_k)}.
  \label{eq:cov}
\end{equation}
The full objective is the convex combination
$\mathcal{L} = \mathcal{L}_{\text{BCE}} + \lambda\, \mathcal{L}_{\text{cov}}$.
$\mathcal{L}_{\text{BCE}}$ supplies a gradient on every candidate
and calibrates the per-candidate probabilities that downstream
selection and the next epoch's hard-negative mining read off the
score. $\mathcal{L}_{\text{cov}}$ is permutation-invariant across
$\mathcal{G}$ and concentrates softmax mass on ground-truth members
relative to in-group negatives, without penalising gold-vs-gold
order. Setting $\lambda{=}0$ recovers a pure-BCE scorer; we
treat this $\lambda$ sweep as a planned ablation and defer the
numbers to a future revision. Top-$K$ selection itself is
performed only at inference and is never differentiated.
